PROJECT OVERVIEW
----------------
Building a comprehensive WhatsApp CRM with:
- Multi-account/multi-session WhatsApp support
- Multi-tenant SaaS architecture
- API integrations (n8n, Zapier, GoHighLevel, Make.com)
- Real-time messaging with WebSocket/Socket.IO
- AI/Chatbot integration capabilities
- Message queue system for reliability

================================================================================
TECH STACK DECISION (Based on Research)
================================================================================

Backend:
- Runtime: Node.js 20+ with TypeScript
- Framework: NestJS (enterprise-grade, modular)
- ORM: Prisma
- Database: PostgreSQL (primary)
- Cache: Redis
- Queue: BullMQ
- WhatsApp: Evolution API (wraps Baileys)

Frontend:
- Framework: React 18+ with TypeScript
- State: Zustand
- UI: Tailwind CSS + Radix UI
- Real-time: Socket.IO client

Infrastructure:
- Container: Docker + Docker Compose
- Storage: MinIO (S3-compatible) for media
- Reverse Proxy: Nginx

DATABASE SCHEMA (Core Entities)
================================================================================

-- Tenants (Organizations)
tenants: id, name, slug, settings, plan, created_at, updated_at

-- Users (Team members)
users: id, tenant_id, email, password_hash, name, role, avatar_url,
       is_active, last_login_at, created_at, updated_at

-- WhatsApp Sessions
whatsapp_sessions: id, tenant_id, name, phone_number, status,
                   qr_code, credentials, webhook_url, settings,
                   last_connected_at, created_at, updated_at

-- Contacts
contacts: id, tenant_id, whatsapp_id, phone, name, email, avatar_url,
          tags, metadata, created_at, updated_at

-- Conversations
conversations: id, tenant_id, session_id, contact_id, status,
               assigned_to, last_message_at, unread_count,
               metadata, created_at, updated_at

-- Messages
messages: id, conversation_id, whatsapp_message_id, direction,
          type, content, media_url, status, metadata,
          sequence_number, created_at

-- Webhook Endpoints (Outgoing)
webhook_endpoints: id, tenant_id, name, url, events, secret,
                   is_active, last_triggered_at, created_at

-- Webhook Logs
webhook_logs: id, endpoint_id, event, payload, response_status,
              response_body, attempts, created_at

-- API Keys
api_keys: id, tenant_id, name, key_hash, permissions,
          last_used_at, expires_at, created_at

-- Message Templates
message_templates: id, tenant_id, name, content, variables,
                   category, is_active, created_at, updated_at

-- Tags
tags: id, tenant_id, name, color, created_at

-- Contact Tags (junction)
contact_tags: contact_id, tag_id

message.received      - New incoming message
message.sent          - Outgoing message sent
message.delivered     - Message delivered
message.read          - Message read
conversation.created  - New conversation started
conversation.closed   - Conversation closed
contact.created       - New contact created
contact.updated       - Contact updated
session.connected     - WhatsApp session connected
session.disconnected  - WhatsApp session disconnected

================================================================================
INTEGRATION PATTERNS
================================================================================

n8n Integration:
- Webhook endpoint for n8n to receive events
- HTTP Request node to send messages via API
- API key authentication

Zapier Integration:
- Webhook triggers for Zapier
- REST API actions for Zapier
- OAuth2 or API key auth

GoHighLevel Integration:
- Webhook delivery to GHL endpoints
- Custom value mapping
- Contact sync capabilities

Make.com Integration:
- Similar to n8n/Zapier
- Webhook + API pattern

================================================================================
REAL-TIME EVENTS (Socket.IO)
================================================================================

Namespaces:
- / (default): Dashboard events
- /chat: Chat-specific events

Events to Client:
- new_message
- message_status_update
- typing_indicator
- session_status_change
- contact_update
- conversation_update

Events from Client:
- join_conversation
- leave_conversation
- mark_read
- typing_start
- typing_stop

================================================================================
SECURITY CONSIDERATIONS
================================================================================

- JWT authentication with refresh tokens
- API key authentication for external integrations
- Multi-tenant data isolation (tenant_id on all queries)
- PostgreSQL Row-Level Security (RLS)
- HMAC webhook signature validation
- Rate limiting per tenant/session
- Encrypted WhatsApp credentials storage
- Input validation and sanitization

================================================================================
RATE LIMITING
================================================================================

WhatsApp (per session):
- Max 200-500 messages/day (conservative)
- Delays between messages (1-3 seconds)
- Gradual warm-up for new numbers

API:
- 100 requests/minute per API key
- 1000 requests/minute per tenant

================================================================================
MESSAGE QUEUE (BullMQ)
================================================================================

Queues:
- whatsapp-outbound: Outgoing messages to WhatsApp
- webhook-delivery: Webhook delivery to external systems
- media-processing: Media file processing

Job Options:
- Retry with exponential backoff
- Dead letter queue for failures
- Priority support
